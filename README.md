# Управление программными проектами — стартовый репозиторий

Здесь вы будете сохранять результаты практических работ дисциплины. Работа в Битрикс24 остаётся в вашем портале, а в GitHub хранятся отчёт, ссылки и скриншоты для преподавателя. Код интернет-магазина писать не нужно.

## Начало работы

1. На странице этого шаблона нажмите **Use this template → Create a new repository**. Не используйте Fork: нужен собственный репозиторий для работ по дисциплине.
2. В поле **Repository name** укажите `project-management`. В **Owner** выберите свою учётную запись. Видимость согласуйте с преподавателем: в публичном репозитории любой человек сможет увидеть загруженные файлы. Для приватного репозитория заранее уточните доступ преподавателя и доступность Actions.
3. Нажмите **Create repository**. Для работы через сайт GitHub клонирование и установка Python не нужны.
4. Откройте [задание второй темы](lesson_02/README.md). Готовые тексты для Битрикс24 находятся в [texts.md](lesson_02/texts.md), заготовка сдачи — в [report.md](lesson_02/report.md).

## Как сохранить работу и запустить проверку

GitHub Actions — автоматическая проверка, которая запускается после сохранения изменений. Коммит — сохранённая версия файлов репозитория. Проверка относится к конкретному коммиту: после исправлений нужен новый успешный запуск.

1. Выполните практику в своём портале. Снимайте ключевые экраны по [списку](lesson_02/README.md#семь-обязательных-скриншотов).
2. Откройте папку `lesson_02/screenshots` в **своём** репозитории. Нажмите **Add file → Upload files**, перетащите семь PNG с точными именами, затем **Commit changes**. Загрузка не маскирует данные — подготовьте безопасные снимки заранее.
3. Откройте `lesson_02/report.md`, нажмите карандаш **Edit this file**, замените все `[[...]]` своими ссылками. Сохраните через **Commit changes**. Не меняйте названия полей и пути к изображениям.
4. Откройте вкладку **Actions**. Если GitHub предлагает включить Actions, подтвердите включение для своего репозитория. Дождитесь последнего запуска **Проверка сдачи** для текущего коммита.
5. Если запуск красный, откройте **Комплект второй темы → Проверить комплект сдачи**, прочитайте ошибки и исправьте названные файлы. После нового коммита проверка повторится. При необходимости используйте **Actions → Проверка сдачи → Run workflow → Run workflow**.
6. Передайте преподавателю ссылку на свой репозиторий и на последний успешный запуск Actions. Закрытый портал не нужно делать публичным: содержание показывают скриншоты; вход в чужую учётную запись не требуется.

**В незаполненном шаблоне проверка должна быть красной:** своих ссылок и снимков ещё нет. Зелёный результат означает, что комплект собран, а не что преподаватель принял работу.

## Что проверяется

Автоматически: заполненность ссылок, отсутствие маркеров `[[...]]` в отчёте, ссылки на семь изображений, формат, размер и наличие PNG. Изображения — не меньше 640 × 360 пикселей, не больше 12000 × 12000 и 10 МиБ каждое. Сохраняйте исходное разрешение экрана; не растягивайте маленькую картинку до требуемого размера.

Преподаватель проверяет содержание: цель и границы проекта, условия трёх задач, исполнителя и сроки, правила резерва, два примера, самопроверку или отзыв и завершение первой задачи. Actions не читает интерфейс Битрикс24, не распознаёт текст на снимках и не проверяет доступность ссылок закрытого портала.

## Безопасность снимков

Не загружайте пароли, коды входа, токены, платёжные сведения и личную переписку. Используйте отдельный портал и вымышленные данные для занятий. Скройте почту, телефон, аватар и посторонних участников; при необходимости скройте адрес портала на снимке. В поле исполнителя можно оставить одинаковую нейтральную подпись «Моя учётная запись», чтобы была видна назначенная роль. Не закрывайте название задачи, её условия, срок, результат и статус. Если конфиденциальны сами ссылки, сдавайте в приватном репозитории с согласованным доступом.

## Локальная проверка — необязательно

Из корня репозитория, Python 3.12 или новее:

```sh
python3 -m unittest discover -s checks -p 'test_*.py'
python3 checks/check_submission.py
```
